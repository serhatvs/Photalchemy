# Track A — Trainable photo-classification and evaluation plan

**Owner:** Serhat Yavuz · **Status:** Draft to review with Ali, Kadir and course instructor. No user photos or trained model have been added.

## Why a custom model?

The MVP uses visual properties of real-world photographs to create cards. Pure color statistics are useful **deterministic features**, not the required own-trained model. This plan proposes training our own **scene-category classifier** to recognize **nature / urban / interior / object close-up**. Scene prediction would influence one aspect of card creation, while color and rarity influence bounded strength. A learned classifier is justified because scene content and framing cannot be reliably inferred from a few fixed color thresholds. **The prediction target and mapping require team approval**: we should not silently substitute this proposal for the original color-based card-class concept.

## Proposed labels and collection

| Label | Positive examples | Exclude / flag as ambiguous |
| --- | --- | --- |
| `nature` | Primarily plants, landscape, sky, natural scenery | Mixed indoor scenes, close-ups dominated by one object |
| `urban` | Streets, buildings, urban structures | Single-object closeups, indoor corridors |
| `interior` | Room-scale indoor environments | A single object taking most of image |
| `objectCloseup` | Main subject is one close object, independently of indoor/outdoor setting | Wide scene with multiple equally strong subjects |

Proposed collection target **~320 photos, about 80/class** from multiple consented sessions, varied lighting and scene conditions. This is a feasibility target, *not* a dataset we claim to already have. Avoid faces, plates, documents and distinctive private scenes. Use existing permission-cleared sources only after checking licensing/consent and redistribution restrictions. No personal user photos are committed.

- Create a stable random/pseudonymous `image_id`; collect `label`, `photographer_pseudonym`, `session_id`, `scene_group_id`, `consent_or_license_ref` and content checksum in a **local/private** manifest. No GPS coordinates in manifest. Store raw photos outside public repo with restricted access and a documented retention/deletion process.
- Team members label independently on a small pilot (~10 per class); write and refine label rubric, record disagreement and exclude or adjudicate ambiguous images. Keep labels based on **image content**, not deterministic color rules generated by code.
- Remove duplicate/near-duplicate photos and EXIF; photos of the same subject/location/session must share a group identifier. Avoid random image-level split across bursts/near duplicates.
- If data quantity, permissions or label consistency are inadequate, reduce ambition **with instructor approval** and document the tradeoff; do not falsify evaluation numbers.

## Leakage-safe splits and reproducibility

1. Define groups based on repeated scene/photographer/session so near-duplicate or same-location images cannot cross training and evaluation.
2. Hold out approximately **20% of groups** as final test set *before* model selection; preserve approximate class coverage when feasible. If only four contributors or too few groups exist, report the weakness; do not call it population-level generalization.
3. On remaining data, use `StratifiedGroupKFold` or `GroupKFold` (e.g., up to five folds **only if group counts permit**). Fit preprocessing/scalers exclusively on training folds.
4. Tune models only using training folds. Freeze pipeline/model/thresholds before final holdout evaluation.
5. Keep random seeds and package versions, manifest schema, transformations, source licenses/consents and training/evaluation scripts versioned. Never store sensitive samples in the repo.

## Baseline versus learned model

- **Trivial baseline:** majority-class prediction and class-frequency baseline.
- **Classical trained baseline:** logistic regression or small tree on brightness/saturation/contrast + HSV/color histogram (features extracted identically per image). Use grouped CV.
- **Own-trained Track A:** train a compact classifier with a clearly logged training process (e.g., small CNN or transfer learning with a learned classification head, then evaluate). Verify interpretation with course staff if pretrained weights are used.
- Do not mistake a pretrained model's unmodified predictions or hand-written palette rules for an own-trained model.

## Metrics and uncertainty

Report per-class precision/recall/F1, macro-F1, accuracy, confusion matrix and grouped-CV fold distribution. Choose macro-F1 as primary metric to reduce majority-class dominance. On final holdout, present **95% grouped bootstrap intervals**, resampling *groups*, not individual near-duplicate images. If groups/folds are too few for meaningful intervals, state the uncertainty and dataset limitation. Compare against both baselines; do not cherry-pick the best seed.

Document compute/training time and feasibility of mobile inference (size, latency on emulator/device), common failure cases, model version and ethical/privacy considerations in a model card.
